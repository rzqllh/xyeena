# Risk register

Residual risks are tracked separately from automated test completion.

| Risk | Impact | Current control | Residual state |
| --- | --- | --- | --- |
| Host reports a skill file but does not activate it | Incorrect runtime behavior | Distinct inventory/eligibility states; require native acceptance | Live validation pending |
| Privileged operation without host-confirmed consent | Unauthorized changes | Fail-closed execution gates, explicit host authority boundary | Live interception pending |
| Untrusted third-party skill instructions | Prompt injection or unexpected actions | No execution during discovery; host trust and scope checks | Review on enablement |
| Unavailable Simpul execution supervisor | Tasks stuck in submitted/pending | Execution-readiness probe and native/inline fallback | Upstream blocked |
| Shared-write concurrency or stale run state | Duplicate changes | Serialization, lease ownership, recovery checks and negative tests | Continue host/OS acceptance |
| Installer modifies user or third-party skills | Data loss | Ownership markers, diff preview, backups and guarded rollback | Controlled through review |
| Unbounded provider usage | Cost/availability loss | Budget ledger, bounded dispatch and cancellation | Depends on provider reporting |
| Evidence generated by the same actor being evaluated | False completion | Independent checker and REVIEW_REQUIRED fallback | Checker quality must be reviewed |
| Package published before live acceptance | Unreliable release claims | Release gates and separate publication authorization | Publication pending |

Critical impact is not equivalent to a known active critical vulnerability. Automated tests cover specified contracts; operational evidence is still required for live scenarios.
