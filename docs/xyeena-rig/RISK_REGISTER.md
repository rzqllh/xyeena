## Worker identifier diagnostics — source hardening (2026-10-26)

Native host adapters continue to reject missing, malformed or placeholder worker identities. Validation errors no longer include raw host-supplied identifiers, preventing incidental credential/path leakage through error messages. This is a source-level defensive change verified by tests, not a live host containment claim.

## Budget ledger input integrity — source fix in PR #47

The previous ledger accepted invalid (including negative and non-finite) usage and estimates, potentially understating consumption. Source validation now rejects those values and prevents duplicate active worker IDs; Simpul with an attached ledger rejects missing or invalid post-run usage. Residual risk remains **provider-side over-consumption before settlement**; these checks are not upstream spending enforcement and require live provider verification before changing OPS-06.

## MCP payload and diagnostic boundary — PR #48

Unbounded structured/direct-object Simpul MCP responses and raw upstream exception/submission errors could exhaust resources or expose private paths in diagnostics. Source now normalizes bounded UTF-8 JSON objects and returns generic transport/submission failures. Residual risk: real MCP server trust, authenticated execution, supervisor lifecycle and filesystem containment remain LIVE BLOCKED.

## Native worker cancellation lifecycle (PR #49)

Previously, an already-aborted native adapter signal could still dispatch a worker; successful runs left abort listeners attached and asynchronous cancel failures could surface as unhandled rejections. Source now blocks pre-aborted runs, cleans up listeners, handles rejected cancellation promises, and redacts host failure details. Remaining limits: actual OS descendant teardown, terminal signaling and provider settlement still need independent live evidence.

## Shared write lock after timeout (PR #50)

Before this source fix, a timeout could release the shared workspace write lock immediately after best-effort cancellation, even with an unresolved adapter operation. Source now retains the lock until the invocation settles. Residual operational risk: an unresponsive worker can block subsequent writes indefinitely within the process, requiring controlled recovery; there is still no OS-native guarantee that descendants stop writing after their parent resolves. Continue LIVE BLOCKED on unverified host containment.

## Unverified isolation claims (PR #50)

A caller-provided isolatedWorktrees flag could previously bypass write serialization without host-proven worktree containment. All writes are now fenced and limited to parallelism one, regardless of that flag. A canceled, unresponsive write can block that workspace pending controlled recovery: this is an intentional fail-closed tradeoff. Host-authenticated worktree isolation and OS descendant ownership remain unverified.

## Native read target leakage boundary

The pre-existing read-tool allow-by-name behavior could permit a native host to read outside the trusted RIG workspace without an Xyeena approval request. Source policy now requires an explicit, contained canonical target for `allow`, denies outside/symlink destinations and asks the native host for approval when target schema is ambiguous. **Residual risk:** native IDE hooks have not been proven to run at all; a security boundary must not be asserted for IDE 2.5.5 without independent live negative acceptance (#34). OS-level sandboxing is not implemented by this policy.

## Owned subprocess descendants on Windows

Previously the portable and Python SDK one-shot adapters only signaled their direct child; spawned descendants could survive timeout or Ctrl+C. Unreleased source now requests Windows tree cleanup using only the owned child PID, with conservative fallback when taskkill is unavailable. Residual risk: a kill request does **not** authenticate full termination, a detached subprocess may escape the tree, PID reuse is theoretically possible, and remote provider requests/spending are not guaranteed to stop; independent host observation remains required for OPS-06/#37. The source handler still returns cancellation before receiving an OS confirmation.

## Release pipeline supply-chain authorization

Previously `publish.yml` contained legacy `main` push/commit-message triggers, credential-token fallback and no release-tag-to-current-main equality gate. The source workflow now accepts only explicit stable GitHub Release publication and refuses version/tag mismatches, non-main commits and registry duplicate versions. It delegates authentication to trusted OIDC. **Residual external prerequisites:** configure npm Trusted Publisher, required human reviewers for the `npm-publish` environment, GitHub tag protection/immutable releases and separate user approval. A YAML environment declaration is not an approval control until reviewers are configured.

## Delegation capability/parallel write assertion hardening

`selectSubagentBackend` now requires **`executionReady === true`** in addition to explicit opt-in, health, callable adapter and scope support. Undefined, false, null, or textual readiness cannot select native/optional workers; fallback stays inline. The selector also refuses parallel writes based on a caller-supplied `isolatedWorktrees` flag; actual host-enforced isolation is not established by that flag. This aligns the public policy view with RIG's shared workspace write fence. The distinct optional Simpul workspace remains outside core acceptance.

## Codex partial-completion false positive

A one-shot Codex JSONL parser previously considered a final agent-message item sufficient without a `turn.completed` event. Exit code 0 could then be misinterpreted as successful execution after a truncated stream. The source parser now requires an ordered terminal event and invalidates prior completion on any later incomplete turn; malformed/missing final evidence is an error, not `executed:true`. The result still requires independent verification and real-host acceptance #36.
